# Транспортное моделирование — доменные знания

В твоём распоряжении проверенный свод правил транспортного моделирования, собранный из четырёх первоисточников:

| Тег | Источник |
|-----|----------|
| `[M]` | MATSim Book, 2016 ed. (214 стр.) |
| `[G]` | А. Э. Горев, «Основы теории транспортных систем», СПбГАСУ, 2010 |
| `[RK]` | ПДД РК, Приказ МВД РК №534 от 30.06.2023 |
| `[SP]` | СП РК 3.03-101-2013 «Автомобильные дороги» (с изм. 25.02.2019) |

Полный набор из ~60 правил с привязкой к страницам — в файле `references/rules.md`. Обращайся к нему когда нужно проверить конкретный параметр, формулу или сослаться на источник.

**Когда `rules.md` не покрывает вопрос:** читай `references/sources.md` — там карта «тема → глава/статья» для всех четырёх источников плюс ссылки где их взять. Используй её чтобы (1) указать пользователю в каком источнике искать ответ и (2) проверить, не положил ли уже пользователь нужную выжимку в `references/excerpts/`.

**Правило честности (критично):** если ни `rules.md`, ни выжимки не покрывают численный или нормативный вопрос — **скажи об этом прямо** и сошлись на источник. Не выдумывай значения. В транспортном моделировании размытое «обычно около X» хуже честного «нет в моих правилах, посмотри [M] гл. 5 / [SP] табл. 7 — можешь проверить?».

## Критические правила — применяй всегда

### Единицы измерения и координаты
- **`freespeed`** в **м/с**, не км/ч. Формула: `freespeed = км/ч ÷ 3.6`
  - 20 км/ч → 5.56 м/с · 50 км/ч → 13.89 м/с · 60 км/ч → 16.67 м/с
  - 90 км/ч → 25.0 м/с · 110 км/ч → 30.56 м/с · 140 км/ч → 38.89 м/с
- **`capacity`** в авт./час, **`length`** в метрах, **`lanes`** — целое число
- **Система координат для Казахстана:** **EPSG:32643** (UTM зона 43N), всё в метрах [M] p.29

### Три концепции скорости — нельзя путать
1. **Расчётная скорость** (СП РК) — геометрический параметр проектирования; задаёт радиусы, видимость, уклоны, **не** поведение транспорта
2. **Лимит ПДД** — юридический максимум скорости по типу дороги и категории ТС
3. **MATSim `freespeed`** — атрибут link'а сети (м/с), скорость свободного потока на конкретном звене

При установке `freespeed` бери лимит ПДД для соответствующего типа дороги (или наблюдаемую скорость свободного потока если есть данные), затем конвертируй в м/с. **Не используй расчётную скорость из СП РК** для freespeed.

### QSim — мобильная симуляция
- **Правило доли выборки:** `flowCapacityFactor` = `storageCapacityFactor` = доля выборки населения.
  Sample 10% → оба = 0.1. Ошибка тут вызывает либо gridlock, либо нереалистичную пропускную способность. [M] p.36
- **`endTime` обязателен:** всегда задавай (например, `30:00:00`). Без него один застрявший агент
  подвешивает симуляцию навечно. [M] p.36
- **`stuckTime`** (default 10 сек): сколько секунд агент стоит на месте до того как его принудительно
  пропускают. Увеличение делает симуляцию менее реалистичной относительно реальных счётчиков. [M] p.36–37
- **Число потоков:** старт от CPU cores − 1. Самый чувствительный параметр производительности. [M] p.34–35

### Scoring (Charypar-Nagel)
- **Параметры по умолчанию** [M] p.110:
  - `βperf = +6 util/ч` (полезность времени активности)
  - `βlate = −18 util/ч` (штраф за опоздание)
  - `βwait = 0` (держать 0 — альтернативная стоимость уже учтена через βperf)
  - `βm = 1 util/денежная_единица`
  - `βtrav,car = −6 util/ч` (в калибровочных workflow часто ставят в 0 — см. C1 ниже)
- **Соотношение βlate / βperf = 3** — следствие модели бутылочного горлышка Vickrey. Сохраняй. [M] p.110
- **Walk `constant` = 0.0 — обязательно:** ASC для пешего режима должна быть зафиксирована на нуле.
  Иначе она накапливается на каждом access/egress плече PT и разрушает калибровку modal split. [M] p.112
- **Утилита активности логарифмическая:** `U = βperf · ttyp · ln(tdur / ttyp)`. Убывающая отдача
  от времени. [M] p.101
- **VTTS** = `(−βtrav + βperf) / βm`. С дефолтами: (0 + 6) / 1 = **6 ден.ед./ч**. [M] p.106
- **Планы замыкаются на 24 ч:** первая и последняя активности должны быть одного типа, иначе MATSim
  выдаст некорректный результат. [M] p.105

### Replanning и сходимость
- **Мультимодальные планы → `SubtourModeChoice`:** нужен когда агенты используют разные режимы
  в течение дня. `ChangeTripMode` назначает один режим на весь план. `ChangeSingleTripMode` меняет
  один случайный trip. [M] p.39
- **Отключение инноваций** ближе к концу: задавай `fractionOfIterationsToDisableInnovation` (например, 0.8).
  Без отключения score не сходится. [M] p.41
- **Селектор планов:** используй `ChangeExpBeta` (стохастический, MNL-based). Не используй `BestScore`
  в одиночку — он навсегда выбрасывает планы с одним случайным плохим score. [M] p.40
- **MSA-усреднение score** (`fractionOfIterationsToStartScoreMSA`): применять вместе с отключением
  инноваций для форсированной сходимости. [M] p.108

### Общественный транспорт
- **3 обязательных файла:** `transitSchedule.xml`, `transitVehicles.xml`, сеть с PT-звеньями. [M] p.92
- **PCU для автобуса = 3.0** (подтверждено и [M] §13.6, и [SP] табл. 2). При downsampling сценария
  пропорционально уменьшай PCU PT-ТС, иначе получишь искусственные задержки по пропускной способности.
- **PT router:** SwissRailRaptor — default с MATSim release 13. Быстрее и реалистичнее старого. [M] p.96
- **`searchRadius`** (default 1000 м): радиус поиска остановок от origin/destination.
  **`maxBeelineWalkConnectionDistance`** (default 300 м): максимальная пешая дистанция до остановки. [M] p.99

## Рабочие паттерны

### Настройка нового сценария
1. Убедись что `flowCapacityFactor` = `storageCapacityFactor` = доля выборки
2. Задай `endTime` (всегда — без исключений)
3. Проверь CRS: EPSG:32643 для Казахстана (в метрах)
4. Проверь что все планы агентов начинаются и заканчиваются активностью одного типа
5. PT: 3 файла на месте, PCU транспорта скорректирован под выборку

### Калибровка modal split (без внешней logit-модели)
1. Поставь `βm = 1`, `βperf = 6`, `βtrav,car = 0` — авто штрафуется неявно через альтернативную стоимость времени
2. Зафиксируй walk `constant = 0.0`
3. Подстраивай ASC (`constant`) для каждого режима итеративно — прогон → сравнить наблюдаемые доли → подстроить → повторить
4. Отключи инновации на ≥80% итераций до того как читать modal split
5. Если modal split правильный, но распределение по расстояниям нет → **сначала проверь freespeed**, не параметры scoring [M] p.113

### Установка `freespeed` для казахстанских дорог
1. Определи тип дороги и находится ли она внутри/вне населённого пункта
2. Посмотри лимит ПДД РК по таблице выше
3. Применяй: если есть GPS/данные счётчиков — бери наблюдаемую скорость свободного потока; иначе бери лимит ПДД как proxy
4. Конвертируй: `freespeed_мс = лимит_кмч / 3.6`

### Диагностика зависшей или медленной симуляции
1. Задан ли `endTime`? (самая частая причина зависания)
2. Не завышен ли `flowCapacityFactor` для текущей выборки? (вызывает gridlock)
3. Не занижен ли `stuckTime`? (агентов слишком агрессивно пропускают — смотри логи на warnings про "stuck")
4. Потоки = CPU cores − 1?
5. PT-ТС: PCU скорректирован под выборку?
6. Планы: первая/последняя активность одного типа?

## Концепции теории транспорта

Когда пользователь спрашивает про общую теорию (не конкретно MATSim-конфиг), применяй:

- **LOS A–F** (Уровень обслуживания): A = свободный поток, F = коллапс/затор. Из HCM. [G]
- **Гравитационная модель** для распределения поездок: `Qij = vi · dj · a / Cij^k`, где k ≈ 2 для
  городских условий. Калибруется по наблюдаемым OD-матрицам. [G]
- **4-шаговая модель:** генерация поездок → распределение → выбор режима → распределение по сети.
  MATSim — activity-based и заменяет шаги 1–3 более богатой поведенческой моделью. [G]
- **Основы теории транспортного потока:** поток q = плотность k · скорость v. Пропускная способность =
  максимальный поток при критической плотности. [G]
- **Выбор режима:** на основе обобщённых затрат (время + денежная стоимость × VTTS). Charypar-Nagel
  scoring в MATSim — это утилитарный эквивалент логит-модели, используемой в классическом mode choice. [M][G]
